# task1_v1 独立扩充评测集V3说明

## 1. 第一阶段完成范围

第一阶段没有修改Task1“语义+逻辑+血缘”三层算法，也没有引入本体。完成的是一套
比原60对回归集规模更大、隔离更严格的半仿真评测链路：

```text
独立业务规格
  → 生成资产元数据、SQL和血缘
  → 固定DEV/TEST
  → DEV选择判定阈值
  → TEST比较关键词基线与三层模型
  → 360资产目录执行Top-K候选召回
  → 输出一对一指标、召回指标和逐样本明细
```

原有64资产/60对数据继续作为代码回归集，V3不会覆盖它。

## 2. V3数据组成

V3数据位于`data/evaluation_v3/`：

| 内容 | 数量 |
|---|---:|
| 基础资产 | 90 |
| 等价重复变体 | 90 |
| 高度相似但口径冲突变体 | 90 |
| 同域干扰资产 | 90 |
| 唯一资产合计 | 360 |
| 重复资产对 | 90 |
| 高度相似但不重复资产对 | 90 |
| 跨业务域明显不重复资产对 | 90 |
| 资产对合计 | 270 |

数据覆盖存款、贷款、会计三个业务域，以及日、月、季度三种时间粒度和全部、
有效、人民币三种统计范围。SQL及血缘参考公开银行核心系统Schema的表命名与字段
习惯，但资产定义和标签仍是确定性半仿真结果。

## 3. 为什么比原数据更可信

### 3.1 生成器与算法隔离

`scripts/build_independent_dataset.py`只使用业务规格、Pydantic数据契约和SQLGlot
语法解析，不导入：

- Embedding和语义相似度；
- 关键词相似度；
- SQL逻辑相似度；
- 血缘相似度；
- 三层融合；
- 阈值校准和Task1服务。

因此生成器不会先读取模型分数，再决定如何生成“有利于模型”的样本。

### 3.2 DEV与TEST隔离

- 30个业务家族进入DEV，共90对；
- 60个业务家族进入TEST，共180对；
- 同一个资产和同一个业务家族不会跨分区；
- DEV的重复样本采用CTE改写，TEST采用子查询改写；
- DEV的难负例采用聚合/过滤冲突；
- TEST采用未在DEV出现的时间粒度、日期字段、度量字段和币种范围冲突。

阈值只根据DEV标签选择。TEST只运行一次并报告结果，不参与阈值选择。

### 3.3 固定清单和哈希

`dataset_manifest.json`记录数量、分布、隔离结果、边界声明以及`assets.jsonl`和
`pairs.csv`的SHA-256。自动测试会核对这些哈希，避免评测后无意修改数据。

## 4. 运行方式

先配置本地Embedding API Key，然后在项目根目录运行：

```powershell
.\evaluate.ps1
```

脚本会：

1. 确定性重建V3数据并验证SQL；
2. 调用当前部署配置指定的在线Embedding服务生成向量；
3. 在DEV上分别校准关键词和三层阈值；
4. 在TEST上完成一对一判重；
5. 将360个资产导入独立SQLite目录；
6. 对90个已知重复对测试Recall@5、Recall@10和Recall@20；
7. 输出端到端自动检测率。

完整测试命令：

```powershell
.\test.ps1
```

## 5. 2026-07-28首次实测结果

以下结果是2026-07-28使用`text-embedding-v3`、1024维配置得到的历史参考结果。
该配置不是业务代码限制；更换模型或维度后必须重新运行评测。TEST包含180对样本，
其中60对重复、120对不重复。

### 5.1 一对一判重

| 模式 | Accuracy | Precision | Recall | F1 | 误报数 |
|---|---:|---:|---:|---:|---:|
| 关键词基线 | 0.661 | 0.496 | 1.000 | 0.663 | 61 |
| 三层模型 | 0.828 | 0.659 | 1.000 | 0.795 | 31 |

在本次半仿真TEST上，三层模型相对关键词基线：

- Accuracy提高16.7个百分点；
- Precision提高16.3个百分点；
- 误报由61对下降到31对；
- 两种模式均识别出60对重复样本。

该结果说明三层证据有明显增益，但Precision只有65.9%，不能宣称达到课题要求的
90%准确率或生产可用水平。

### 5.2 误报分布

三层模型的31个TEST误报为：

| 场景 | 误报数 |
|---|---:|
| 日期字段口径冲突 | 15 |
| 时间粒度冲突 | 9 |
| 币种范围冲突 | 7 |
| 度量字段冲突 | 0 |

这说明当前SQL逻辑指纹能够识别度量字段变化，但对日期字段、时间粒度和币种过滤
变化仍不够敏感。血缘同源且语义高度相似时，融合总分仍可能超过0.89阈值。

### 5.3 全库候选召回

TEST的60个重复资产对在360资产目录中的结果：

| 指标 | 结果 |
|---|---:|
| Recall@5 | 0.200 |
| Recall@10 | 0.683 |
| Recall@20 | 1.000 |
| 端到端自动检测Recall@20 | 1.000 |

当前混合召回必须保留Top-20才能覆盖全部已知重复资产。Top-5和Top-10仍偏低，
说明候选排序还需要优化，不能为了节省计算量直接把Top-K调小。

## 7. 结论与边界

第一阶段已经证明：

1. 代码可在更大资产目录中运行；
2. 三层模型在该独立半仿真集上优于关键词基线；
3. DEV与TEST的表现差异能够暴露未见冲突类型，而不是继续得到不可信的100%；
4. Top-K候选召回和三层精排已经形成完整链路。

仍未证明：

1. 在真实银行资产上Precision或Accuracy达到90%；
2. 标签符合银行业务专家最终判断；
3. SQL缺失、血缘错误、描述过时和解析失败时系统能够可靠降级；
4. 当前权重和阈值具有跨银行、跨业务域的普适性。

下一阶段应优先补充缺失/错误元数据挑战集和逻辑层细粒度口径特征；真实银行数据
到来后，再执行盲标、双人一致性和最终验收评测。
